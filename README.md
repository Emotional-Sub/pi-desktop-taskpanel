# Task Panel —— PI-Desktop 的实时任务清单面板

一个 PI-Desktop 插件，在独立面板窗口里实时显示 Agent 的任务清单。每个对话一张可折叠卡片，**卡片标题用你给对话起的真实名字**，多个正在跑的任务同时显示、互不覆盖。

- ✅ **真实会话名。** 卡片标题就是你给对话起的名字，实时从本机数据库读取，改名后自动跟上。
- ✅ **多任务并列。** 每个正在跑的会话一张卡片，手风琴排布，运行中的排在最前。
- ✅ **卡片可折叠。** 单张随意折叠/展开，也能一键全部折叠/展开。
- ✅ **拖动排序。** 按住卡片左侧的 ⋮⋮ 手柄上下拖动调整顺序（也可聚焦手柄后按 ↑/↓），一次按住可连续越过多张卡片，卡片跟着指针走，拖到列表上 / 下边缘会自动滚动；顺序记在本地；新出现的会话排在最前；右上角「默认排序」一键恢复自动顺序。
- ✅ **左划删除。** 卡片头向左划露出「删除」按钮，点它移除这张卡片；向右划回去或点别处收起。删掉的卡片在该会话有新动静（重新推送清单 / 开新一轮对话）之前不会再冒出来。
- ✅ **实时状态。** 每张卡片显示运行中 / 已结束（完成 · 中止 · 出错），带进度条和 已完成 / 进行中 / 待办 / 受阻 计数。
- ✅ **主动发现。** 正在运行但还没推送清单的会话，也会显示成一张占位卡片。
- ✅ **中 / 英切换。** 面板右上角一键切换界面语言，默认中文、记住你的选择，不跟随宿主语言乱跳。
- 🔒 **权限最小、只读。** 只从本机 `pi.sqlite` 读取会话标题和轮次状态；绝不读消息正文、绝不写数据库，不联网、不用剪贴板、不用 shell。

## 工作原理

插件分两半，通过一个小状态文件协作：

```
                 task_update（Agent 工具）
   Agent  ─────────────────────────────►  把每个会话的清单写到
                                           <数据目录>/state.json
                                                    │
   pi.sqlite（只读）── 真实标题 + 轮次状态 ──────────┤
                                                    ▼
   面板窗口  ◄──── task.pull（约 0.7s 轮询） ────  合并 & 渲染卡片
```

- **`task_update`** 是一个 Agent 工具。模型带上完整清单调用它（`{ title?, tasks: [{ text, status, note? }], open? }`），插件按工具调用所在的会话 id 分开存储，所以并发的多个对话互不干扰。
- **标题和实时状态** 直接从 PI-Desktop 本机的 `pi.sqlite` 读取（各会话的 `sessions.title` 和最新一条 `turns.status`），**只读打开**。这就是标题始终是真实会话名、且改名后会跟着变的原因。
- **面板** 轮询 `task.pull`，把存储的清单和实时的标题/状态合并，每个会话渲染成一张可折叠卡片。

> **为什么读数据库而不是用宿主 API？** 插件的会话 API（`pi.session.get`，权限 `session.read.own`）的 "own" 范围只覆盖插件自己 import 进来的会话——它看不到你的真实对话，也就拿不到标题。只读 `pi.sqlite` 是同类插件（比如 Session Notify）拿到真实标题的通行做法。完整来龙去脉见 [CHANGELOG](CHANGELOG.md#040)。

## 安装

### 用打包好的 `.piplug`

1. 打包（或从 [Releases](../../releases) 下载现成的）：
   ```sh
   npm run pack
   ```
   会生成 `dist/local.taskpanel-<版本号>.piplug`。
2. 在 PI-Desktop 里打开**插件**页面，导入这个 `.piplug` 文件。
3. 从命令面板打开面板：**任务清单: 打开面板**（英文界面下是 **Task Panel: Open**）。

升级时导入新版本的 `.piplug` 即可，导入后面板才会用上新代码。

命令面板里搜「任务清单」或「Task Panel」能找到全部三个命令：

| 命令                       | 作用                                                         |
| -------------------------- | ------------------------------------------------------------ |
| 打开面板 / Open            | 打开或前置面板窗口。Agent 调 `task_update` 时也会自动打开。   |
| 清空全部 / Clear all       | 移除所有卡片；正在运行的会话在重新推送清单或开始新一轮前不会冒出来。 |
| 渲染示例 / Render sample   | 推一份示例清单，看看面板长什么样。                             |

插件申请两项权限：`ui.panel` 和 `agent.tool.register`。

### 让 Agent 主动用它

工具 `task_update` 的描述里已经内置了推送纪律（每完成一项立刻推、别攒着、长任务定期回推）。而工具描述每轮都随 schema 注入模型上下文——所以**装了插件就自动生效，不用在 AGENTS.md 里加规则**，也比只在开头出现一次的 AGENTS.md 更抗长会话的上下文压缩。

说明：清单进度（几项完成、每项状态）只在模型调 `task_update` 时才产生，`pi.sqlite` 与任何本机文件都不存这类数据，插件无法凭空算出或代推；面板能做的是「检测停更并显眼提醒」（运行中但超 10 分钟没推 → 卡片标黄），实际进度仍须由会话中的模型主动推送。

## 开发

需要 Node.js ≥ 22.13（测试和插件查标题都用到内置的 `node:sqlite` 模块，22.13 起不加 `--experimental-sqlite` 也能用）。插件运行在 PI-Desktop 自带的 Node 里，那边拿不到 `node:sqlite` 时会降级用清单自带的标题，不会报错。

```sh
npm test        # 工具逻辑测试 + 面板渲染测试（不需要宿主）
npm run pack    # 打包出 dist/local.taskpanel-<版本号>.piplug
```

测试全程在 Node 里跑：mock 掉 `pi` 桥接和 DOM，用 `node:sqlite` 建一个临时 `pi.sqlite` 来验证标题/状态这条链路。不需要运行中的 PI-Desktop。

渲染测试用的是极简 DOM 桩，没有真实布局、事件冒泡和指针捕获。改了拖动 / 左划这类手势，请再到真实浏览器里试一遍：直接用 Chromium 内核浏览器（Edge / Chrome）打开 `src/renderer/index.html`，没有宿主桥接时面板自动进入演示模式，显示三张示例卡片，可以直接拖动、左划、折叠。0.5.0 的「不能连续拖动」就是只在真实浏览器里才会出现的问题。

## 目录结构

```
src/
  manifest.json        插件清单（id、权限、工具 + 命令声明）
  main.js              插件进程：task_update 工具、state.json、pi.sqlite 读取
  renderer/
    index.html         面板结构
    panel.css          面板样式（深色优先，浅色走 prefers-color-scheme）
    panel.js           面板逻辑：轮询、合并、手风琴渲染、折叠、拖动排序、左划删除、中 / 英切换
scripts/
  pack.js              打包成 STORED 模式的 .piplug（无外部依赖）
test/
  test-taskpanel.js    main.js 逻辑（会话隔离、sqlite 标题/状态、主动发现、删除后不回弹、降级）
  test-render.js       panel.js 渲染（卡片、折叠、状态、实时重渲染、语言切换、拖动 / 左划手势）
```

## `task_update` 工具

| 字段    | 类型                                  | 说明                                                                       |
| ------- | ------------------------------------- | -------------------------------------------------------------------------- |
| `title` | 字符串（可选）                        | 清单名。面板优先显示真实会话名，此项仅在拿不到会话名时兜底。                |
| `tasks` | `{ text, status?, note? }` 的数组     | 完整清单，按显示顺序。每次都传全量，会覆盖本会话这一张卡片。传空数组则移除卡片。 |
| `open`  | 布尔（可选，默认 `true`）             | 是否打开 / 前置面板窗口。                                                   |

`status` 取值：`todo`（默认）、`doing`、`done`、`blocked`。

## 隐私

插件**只读**打开本机 `pi.sqlite`，且只读 `sessions` 的标题和最新 `turns` 的状态/时间戳——绝不读任何消息内容。它不写数据库、不发任何网络请求、不用剪贴板、不用 shell。清单文本只来自模型的 `task_update` 调用，存在插件自己的数据目录里。
